**Why the `} else {` approach was abandoned:**
```java
catch (Exception e) {
    pResult.set("too_many");
    return;
    } else {                    // SYNTAX ERROR: 'else' without 'if'
    pResult.set("error");
```

The generated handler code has no leading `if` statement to pair with `else`. Additionally, Java has no way to discriminate exception types at runtime inside a single `catch (Exception e)` block (unlike PL/SQL which checks conditions at the exception level). The only semantically correct approach would be multi-catch by mapped exception types, which is a separate concern.

**What #54 already resolved:**
- `_merge_duplicate_catches` was terminating catch body scans on any `}` (naive), causing inner nested catches to be eaten — producing bracket mismatches
- The fix added brace-depth tracking: only breaks at matching scope depth
- This eliminated the compilation errors described in Issue #56
