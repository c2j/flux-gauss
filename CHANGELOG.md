# Changelog

## [0.6.31] - 2026-11-25

### Fixed
- Schema-qualified package names (`REPRO.PKG_X` form): `CREATE PACKAGE`/`CREATE PACKAGE BODY` with `END schema.pkg;` terminators were silently parsed as 0 packages — the converter exited 0 and emitted only skeleton output. Upgraded the bundled ogsql-parser to v0.11.1 (upstream fix in ogsql-parser PR #344) so schema-qualified `END` is recognized; the 0-package extraction WARNING added in 0.6.30 is retained as a guard.
- Affects 0.6.28–0.6.30: inputs using schema-qualified package names produced empty output with a successful exit code — upgrade recommended for schema-qualified package users.

## [0.6.30] - 2026-11-25

### Fixed
- issue #136 — seven root-cause clusters behind `mvn compile` failures in generated projects (all 8 repro cases now compile):
  - **A/G (call arity)**: cross-package and same-package calls pad missing args by the callee's declared parameter types (`DEFAULT NULL` stays boxed `null`, primitives get `0L`/`0`/`false`, `DEFAULT ''` → `""`) instead of unconditional `null`; relaxed-arity fallback resolves the smallest signature ≥ call-site arity; `this.<fn>` self-call return types feed BigDecimal coercion (`BigDecimal.valueOf(Long)` not a blind cast)
  - **C (cross-package OUT)**: `process_procedure_call` selects the overload whose arity best fits the call site (exact → smallest ≥ → widest) and unwraps the caller's own OUT `AtomicReference` before coercing into IN slots
  - **B-OUT (refcursor)**: residual references to a refcursor OUT param promoted to a `List` return degrade to a comment/`null` instead of `.set()` on a removed variable
  - **F (mapper binds)**: `@Param` bind names deduped across proc params, extra params, local-var refs and package-var refs — no more duplicate `@Param("n")`
  - **D (coercion matrix)**: String-returning calls assigned to numeric targets parse via `Long/Integer/Double.parseX(String.valueOf(..))` instead of an illegal `(Number)` cast; numeric literal args into `String` params emit `String.valueOf(..)`
  - **E (collections)**: `TYPE ... IS TABLE OF` constructors emit `new java.util.ArrayList<elem>()`; numeric-range FOR bounds coerce record/Map `Object` reads through null-safe `Optional...orElse(0L)` and suffix `L` for boxed `Long` counters
  - **B-XMLDOM / builtin packages**: `DBE_XMLDOM.*`, `DBMS_*`, `UTL_*` etc. are checked before the self-call `ends_with` match, so unresolved builtin calls degrade to compilable `/* TOBEFIX */ null` instead of phantom `this.*` calls
  - **Silent drop**: inputs that parse into statements but extract 0 packages/0 procedures now emit a WARNING in the conversion report (root cause: ogsql-parser rejects schema-qualified `END schema.pkg;` — upstream fix in ogsql-parser PR #344)
- Affects output generated by 0.6.28/0.6.29 wherever the above patterns appear — upgrade recommended if generated projects fail `mvn compile`.

## [0.6.29] - 2026-11-25

### Fixed
- `sanitize_java_line` template defect: each `String.valueOf(null)` rewrite net-added one `)` (regex group `$2` captured the closing paren AND the template appended a literal `)`), breaking paren balance inside nested calls → generated Java failed `mvn compile` with `';' expected`/`')' expected` while the converter exited 0 (#134, introduced in 0.6.28). Affects 0.6.28 output wherever NULL literals appear inside nested `String.valueOf(...)`/function-call arguments — upgrade to 0.6.29 if generated projects fail compilation for no obvious reason.

## [0.6.28] - 2026-11-24

### Added
- `composite_type_shims` config: declare shim record types (`sql_type` / `representation` / `fields`) so map_object-style composites lower to typed parallel `List` fields — constructor seeding, `f || x` append, `'{}'` reset (AST-detected, incl. `::cast`), 1-based subscripts, `array_position`/`array_length` Optional semantics; shim `T[]` fields resolve element-wise (`integer[]` → `List<Integer>`); generated tests seed populated map fixtures for shim OUT params

### Fixed
- Control-flow defect cluster moved up from delivery postprocess (#132): precise fallthrough analysis (structured brace matching, if-chain/try-catch/loop-exit), dead code commented as a unit (no orphan catch/brace), illegal `&& (null)` boolean operands degrade to `false`, nested range-for reuses outer counter (save/restore)
- Review fixes (#132/#133): fallthrough scan boundary (last line eligible), literal-true loop detection (no substring match; enhanced `for (x : xs)` is finite), Optional-producing operands (`array_position`/`array_length`) unwrap in arithmetic/comparison/coercion (`Number::longValue`/`intValue`, NULL preserved for boxed targets), `'{}'` concat operand is a no-op not a reset, shim array element types preserved, `IS [NOT] NULL` sentinel params keep boxed signatures (`in_param_signature_type` shared by service signature, IsNull folding, test matchers)
- Literal/cast cluster: `String.valueOf((Object) null)` at emission (`//` lines excluded), `AtomicReference<Long>.set()` int literals get `L` suffix, `(Number)` cast operand parenthesized
